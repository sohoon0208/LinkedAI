# Completion report

Report the actual chronological uppercase sequence, one concise line per
event. The normal main result is:

1. `LUNA RECON` — facts, reproduction, and scope.
2. `PACKET` — compressed decision evidence and objective.
3. `ASTRA HIGH PLAN` — strategy, scope, acceptance criteria, and verification.
4. `LUNA MAX EXECUTION` — bounded edits, checks, and profile-appropriate
   freshness evidence.
5. `SOL LIGHT VERIFY` — independent criterion decision and balanced completion
   gate. Use `SOL FULL VERIFY` for DEEP routing.
6. `FINAL STATE` — `DONE` or the exact incomplete state.

Include retries, replans, evidence requests, and blocked stops in their actual
position. Report requested and host-confirmed model/effort plus the actual
agent ID for every stage. Use uppercase labels exactly: `LUNA`, `ASTRA`, and
`SOL`.

Include:

- TIER; dispatch mode; workflow variant; approval state (`AUTO` in V8).
- ASTRA PLAN COUNT / limit; SOL VERIFICATION COUNT / limit; LUNA ATTEMPTS /
  limit.
- `TOKENS`: measured participant totals or `UNAVAILABLE`/`PARTIAL` coverage.
- `STAGE TOKENS`: explicit intervals, residuals, and reconciliation when
  supplied.
- `TOKEN SCOPE`: whether all participants, controller work, and final response
  are included.
- Missing runtime/visual evidence, external/manual steps, and required user
  action.

Never infer exact provider tokens from packet length or model names. A
pre-final snapshot cannot include the final response. Do not run another model
solely to restate a token number.

For the main workflow, only SOL `DONE` plus a passing `check-run` is a
successful final state. Echo Mode must report its distinct sequence and
`LUNA MAX VERIFY`; it may not relabel LUNA verification as SOL verification.
